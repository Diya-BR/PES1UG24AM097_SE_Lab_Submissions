# Lab 3: Component Modelling & Architectural Pattern Selection

## Objective

Evaluate architectural styles, select an appropriate style for the assigned scenario, and create a UML component diagram showing components, interfaces, and dependencies.

## Scenario

The handout presents a **Self-Service Coffee Kiosk System**. The system supports coffee selection, drink-size selection, credit-card payments, receipt printing, touchscreen interactions, and storage of menu and pricing information.

## Activities

- Review the scenario and identify functional and non-functional requirements.
- Compare Layered, Microservices, and Client-Server architectural styles.
- Select an architectural style and identify at least five system components.
- Model component interactions and interfaces using appropriate UML notation, including provided and required interfaces where appropriate.
- Document the architectural choice and justify it using scenario-specific reasons, a security advantage, and a performance benefit.

## Deliverables

- **Component diagram:** PNG or PDF, with at least five components and at least four interfaces, showing data flow and component interactions.
- **Written justification:** A document of no more than one page, exported as PDF, describing the selected architecture, two scenario-related reasons, one security advantage, and one performance benefit.

## Tools

- draw.io, Lucidchart, StarUML, or another UML modelling tool
- PDF export

## Files
Component Diagram image and report pdf.
