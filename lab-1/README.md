# Lab 1: Requirements Engineering & UML Use-Case Modelling

## Objective

Identify and document system requirements and represent the system's functionality using UML use-case modelling.

## Problem Scenario

**Alumni Mentorship & Mock Interview Platform** — the assigned problem statement describes connecting student mentees with alumni mentors, supporting domain-based mentor matching, session booking, and post-interview scorecard recording.

## Work and Deliverables

- **Requirements table:** Exactly five functional requirements (FR-001 to FR-005) and two non-functional requirements (NFR-001 and NFR-002). Each requirement should include its ID, type, description, priority, acceptance criteria, and rationale as applicable to the handout.
- **UML use-case diagram:** Show the actors and primary use cases, including at least one `<<include>>` and one `<<extend>>` relationship.
- **Use-case flow specification:** A one-page specification for one core use case, including preconditions, postconditions, the main success scenario, and one alternate flow.

## Purpose

This lab focuses on translating a problem statement into clear, testable requirements and modelling user interactions before implementation.
